02

Verification flow

  1. 1
    SubmittedA player sends data through a structured GitHub Issue Form. The workflow automatically starts it at Needs review.
  2. 2
    Needs reviewThe report is source material only and is not trusted automatically.
  3. 3
    Cross-checkingValues are compared against screenshots and, where available, independent reports.
  4. 4
    Verified candidateThe evidence is consistent enough for a maintainer decision, but nothing is published yet.
  5. 5
    Maintainer approvedApplying the approval label creates a dedicated publication branch and pull request. Main is never written directly.
  6. 6
    PublishedOnly after the controlled publication pull request is merged is the source issue marked Published.

A rejected report can be marked status:rejected at any review stage. The automation keeps only one review-status label on each supported submission.
