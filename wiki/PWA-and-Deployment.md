# PWA & Deployment

TGM Companion is deployed as a static Progressive Web App from the repository root.

## GitHub Pages

GitHub Pages publishes from `main` and the repository root. There is no normal build step.

Important deployment details:

- `.nojekyll` keeps the static file structure unchanged.
- Relative paths must continue to work under `/tgm-companion/`.
- `manifest.webmanifest` defines the installed app identity, icons, scope, and shortcuts.
- `sw.js` manages the offline cache and navigation fallback.
- `src/app/pwa.js` handles install/update UX.

## When to bump the service-worker cache

When a change modifies runtime/static files that installed clients must refresh, update `CACHE_VERSION` in `sw.js`.

Examples include changes to:

- HTML pages in the app shell;
- JavaScript controllers/modules;
- CSS used by cached pages;
- static data needed offline;
- other files explicitly precached by the service worker.

Documentation-only repository changes, Issue Forms, or maintainer docs do not require a PWA cache bump unless the app actually caches or renders those changed files.

## App-shell checks

When changing offline/PWA behavior:

1. Keep the app-shell list aligned with required files.
2. Confirm the service worker installs and activates.
3. Confirm the manifest loads without errors.
4. Test a reload while offline.
5. Confirm update behavior for an already-installed client.

## CI

`.github/workflows/test.yml` validates pushes and pull requests. Do not merge required changes while the required `test` check is incomplete or failing.

Publication PRs generated by Community Data automation may also receive an explicitly dispatched CI run on the publication branch.

## Backup branch

`.github/workflows/backup.yml` maintains `backup` automatically:

- after pushes to `main`;
- on its scheduled check;
- using fast-forward-only updates;
- without force-pushing backup history.

Do not commit manually to `backup`, and do not use it as the Pages deployment source.

## Community feed deployment

`community-data.yml` publishes the generated Community Data snapshot to the separate `community-feed` branch. The Community Data page reads that generated snapshot and falls back to its local cached/static source where implemented.

The feed is review information, not the maintained calculator dataset.

## GitHub Wiki sync

The GitHub Wiki source is stored under `wiki/` in `main`. `.github/workflows/wiki.yml` publishes that source to the repository Wiki after merged Wiki-source changes. The main repository remains the reviewable source of truth for maintainer documentation.
