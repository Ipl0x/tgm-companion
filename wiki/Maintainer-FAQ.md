# Maintainer FAQ

## Why did a new data issue not immediately change the planner?

Because community submissions are evidence only. They must be reviewed, approved, integrated into the maintained dataset/Wiki, pass CI, and be merged.

## Why does a new issue start at `status:needs-review`?

That is the safe default. A submitted screenshot/value is not trusted automatically.

## Can I skip directly to `status:published`?

No. `Published` is system-owned. The Community review workflow only applies it after the controlled publication PR is merged.

## What does `status:approved` do?

It creates/refreshes `community/issue-<number>-approved`, exports the normalized approved source record, opens a publication PR, and dispatches CI.

Approval prepares publication; it is not publication itself.

## Why is the approved JSON record not enough?

The JSON record preserves the reviewed submission as source/audit material. A calculator or in-app Wiki change still needs to be added to the maintained application source when required.

## Why can `0` not be used for missing values?

Zero is a real game value. Unknown means the source did not provide/confirm the value. Treating unknown as zero corrupts calculations/data quality.

## What is Original Time?

For Investments, it is the game's base/unbuffed investment time. It must not be reduced by player Investment Buff, VIP, Family Helps, or another speed modifier.

## When should I bump the PWA cache?

When runtime/static files changed and installed clients need a new cached app shell. Documentation-only repository changes do not normally require a bump.

## Why is `backup` not used for deployment?

GitHub Pages uses `main`. `backup` is an automation-maintained mirror for safety/reference.

## Can I manually edit `community-feed`?

Not as the maintained fix. It is generated from issues. Fix the issue data/parser/workflow and let the feed regenerate.

## Can I edit the rendered GitHub Wiki directly?

Temporary edits are possible through GitHub, but the maintained source is `wiki/` on `main`. The next sync can overwrite direct rendered-Wiki edits.

## Why is Freight Truck still WIP when some investments are complete?

Completeness is tracked at different levels. One investment can have all its levels while other category nodes remain unknown. Category aggregate behavior should not be enabled until sufficient source data exists.

## What tests should I run?

Use:

```bash
npm test
```

CI also syntax-checks source/scripts and verifies required files.

## A PR generated by automation exists. Can I merge it immediately?

No. Review it like any other publication PR: source issue, normalized record, real integration, tests, CI, and unrelated diff.

## A bad change is already live. Should I reset `main`?

Normally no. Use a revert or forward-fix PR so history remains auditable. See [Rollback & Recovery](Rollback-and-Recovery).

## Where do security issues go?

Follow `SECURITY.md`. Sensitive vulnerability details should not be posted as a normal public issue.
